# 轻量 GLB 与现有 Canvas 2D 接入

## 已验证的取舍

天启坦克母版为 1,924,286 三角面、79,170,168 字节。用户在真实 GLB 对比后认可约 3 万面作为游戏用默认起点，当时母版保留在本地，能够重新导出。这是预算依据，不是对所有资产画质的保证。

本次实际文件：

| 版本 | 文件字节数 | 内嵌贴图字节数 |
|---|---:|---:|
| 20 万面，普通 GLB，有切线 | 17,026,332 | 7,342,582 |
| 20 万面，Draco | 8,986,972 | 7,342,582 |
| 3 万面，普通 GLB | 8,412,984 | 7,342,582 |

面数更少不一定显著减少下载体积，必须区分几何和纹理占比；不同压缩方式的大小也不是单纯的面数对比。Draco 减少下载字节，不减少解码后的三角面。30k 文件未使用 Draco，不要误标。

## 可恢复的本地优化

1. 读取模型清单与 glTF 扩展、mesh/primitive、材质、纹理、动画及骨骼信息。计算输入哈希，另目录输出。
2. 设定全模型约 30k 三角面目标，用已有可用的 meshoptimizer / glTF-Transform 等简化链路；记录工具版本和完整参数，不假定某个历史 CLI 参数仍存在。保留部件边界、UV、法线、材质和需要的骨骼数据。
3. 简化后检查实际三角面数，避免只报告目标值。法线贴图在缺失或错误切线时可能出现接缝，按实际材质需要重建切线并验证。
4. 用同一个参考模型框定、相机、比例、灯光、背景对比母版与候选，并检查游戏实际显示大小。至少观察主要轮廓和容易退化的细长结构；明显损坏时提高预算并记录理由，不能以“达到了 30k”替代视觉检查。
5. 纹理压缩另做可辨别候选。2K 可作为已有贴图的保留起点，不是所有资产必须使用的配置。WebP 和 KTX2 支持不同；当前 GLB 查看器验证了 WebP，尚未配置 KTX2 解码器。
6. 对压缩文件执行真实加载／解码。Canvas 精灵烘焙器当前使用普通 GLTFLoader，没有配置 Draco；需要输入普通 GLB或明确接入解码器。不要用解压文件替换测试输入，却声称验证了压缩格式。
7. 输出轻量 GLB、参考输入及生成记录位置、原始 GLB 的本地留存状态（有则标明位置）、文件清单与输入/输出哈希、实际三角面、几何/纹理字节、贴图尺寸、简化与压缩配方、检查结论。归档原件不代表玩家要下载原件。

已有模型不自动重跑 ImageGen/Meshy，也不为简化额外调用付费 remesh。若用户另有授权和选择，再按实际 API 参数执行。

## Canvas 2D 验证路径

仓库已有两条不同用途的渲染路径：

- 主游戏：Canvas 2D `src/renderer.ts`，地图、精灵绘制、排序、选择、移动。
- 独立 3D 工具：`prototypes/3d/` 与 GLB 查看器，适合检查网格和材质。

`npm run viewer:glb` 默认打开本机 4175 端口；`/canvas/` 是同服务的旧引擎精灵战场。查看器目录由 `GLB_VIEWER_DIR` 定位，Canvas 页目录由 `GLB_CANVAS_DIR` 定位，当前源码随仓库保存在 `tools/glb-compare/` 和 `tools/canvas-hd-preview/`，自制运行素材在 `assets/hd/`；母版和原版提取缓存不随仓库迁移。查看启动脚本与 README，不假定任意工作树都有缓存或工具。

出图工具与初始样本在相邻 `canvas-hd-preview/` 中，`bake.js` / `bake.mjs` 保存正交相机与烘焙配方。对新资产设置实际原精灵的帧大小、锚点、朝向与游戏身份映射，不直接套用坦克值。

- 原投影地格为 60×30，正交烘焙 30°俯角可对应其 2:1 地面投影；仍需验证模型自身轴向和朝向帧顺序。
- 高清 PNG 采用 `pixelRatio: 4` 的可选元数据。源帧像素为原逻辑帧的 4 倍，绘制尺寸与锚点除以该值。没有字段的旧素材继续使用 1；不要把单位放大四倍，也不要把地图格子放大来迁就源图。
- 检查不透明轮廓的真实宽高，不只比较空白帧框。已对谭雅按原版约 28 逻辑像素高做过体型校准；其他模型需各自测量。
- 现有样本：坦克 16 朝向、谭雅 8 朝向程序动作、两种建筑固定视角，另有阵营遮罩及 Canvas 事件特效。具体覆盖与局限见 [动作与阵营色](animation-and-team-colors.md)，不能据此推算完整游戏动画包大小。
- 静态精灵不需要运行时保留 GLB。验证页面只使用 `2d` context，没有 Three.js/GLB 网络请求，且选择、移动、排序、原版切换都实际可用。
- 新素材正式接入仍需要适用的走路、开火、死亡、建造／损毁状态、团队色遮罩、阴影和炮塔分离。只按本次用户要求的范围完成，不虚构已有动画。

## 精简分支与归档边界

默认发布高清参考图、实际生成记录、经验证的轻量 GLB，以及按需生成的 Canvas 精灵。
保留实际使用的高清与多视角输入，按哈希去重，避免重复图片或仅保留缩略图。
母版 GLB 可按需本地留存；FBX、Blender 工程、重复独立贴图、预览和 ZIP 不默认保留，
也不把这些导出格式再次批量推到 LFS。已有归档不因规则变更而自动清理。
参考图重新生成不保证相同模型或免费；对同一模型直接重新减面需要原始 GLB。
复现工具及锁定依赖在 `tools/model-opt/`。
本次 1K WebP 是经对照验证的分发选择；法线／金属粗糙度贴图在缩放后使用无损
WebP，颜色贴图质量为 85，切线重新计算。新资产仍需独立验证，不机械套用。
Canvas 烘焙器默认使用仓库四个 `assets/hd/models/<asset>/30k.glb`；
`RA2_MODEL_DIR` 仅为本地母版对比的可选覆盖。
GitHub 上删除历史引用不会自动释放旧 LFS 配额；需要按官方文档请求对象清理。
