# 方向映射与运动行为验收

用于可移动单位、朝向精灵烘焙及用户要求的 3D 交互预览。仅交付静态资产时记录轴向与朝向样张，不强制新增移动或攻击功能。

## 先确认模型与坐标约定

逐资产在未施加场景朝向的模型上检查正面、侧面、俯视；结合原 SHP/VXL/HVA、车头／驾驶室、履带纵轴、面部、武器与游动姿势确认前向。不能假设所有 GLB 朝 +Z，不能复制另一模型的 90°／180°补偿，也不能只凭包围盒长边确定正反。

记录资产 hash、上轴、地面轴、前向向量所在的坐标层级、导入节点变换、引擎角度零点／正方向及证据。区分模型轴、世界轴、相机轴和精灵朝向索引。前向转换须包含实际父子变换，避免轴修正重复应用；摄像机旋转不能改变单位世界朝向。

当前 Canvas 3D 实例：世界 X/Z 为地面、Y 向上；引擎角度为 `atan2(ΔZ, ΔX)`。在导入场景已经应用节点变换、尚未添加外层朝向时，天启／采矿车车头为 −X，谭雅／飞行兵面朝 +Z，乌贼原版游动以外套膜尖端 −Z 朝前。对应无额外旋转的 Y-up 外层 yaw 为 `atan2(forward.z, forward.x) - engineAngle`。这些是当前资产的实测值和约定，新资产必须重新确认。

## 行为要求

- 正常前进时，车辆沿车头与履带纵向前进，步兵／飞行兵沿动作定义的前向移动；水生单位依实际游动证据。不能横滑或无意倒着走。倒车、侧移、后退射击仅在已有规则或明确动作允许时例外，分别验证。
- 区分车体行驶、炮塔瞄准、炮管后坐和骨骼攻击轴。开火方向、枪口位置与目标一致，后坐沿炮管反向；不能沿一个未经校准的 `translateZ` 横向震动。未分离炮塔的静态资产如实标缺失，不以整车旋转冒充独立炮塔。
- 检查转弯、往返、移动→停止→攻击→再移动，以及适用的走跑／匍匐／游泳／飞行切换。动作局部变换或 root motion 不能额外转向、镜像或叠加第二份世界位移。
- 检查手动观察转向后重新下达移动指令，观察偏移不得残留为斜行；暂停、逐帧、恢复、镜头四向旋转后行为仍正确。建筑无行驶要求，检查实际支持的固定朝向／炮塔状态。

## 必须以实际行为验证

1. 按本次涉及的每种可移动模型，至少验证八个地面方向和一次往返／转弯。修改共享映射或用户要求全查时覆盖全部受影响模型，不只测首个样本。
2. 在真实消费页面下达移动指令，采样非零位移与渲染后的模型前向。以实际路径切线为准，不能假定寻路的第一段恰好指向最终目标。开阔测试通道避免重叠挤开混入方向测量；再在实际场景检查转弯和绕障，不为通过测试修改游戏碰撞规则。
3. 将已由几何／原图独立确认的前向变换到世界坐标，与归一化实际位移比较；正常直行应同向（例如 dot > 0.99，阈值按转向机制说明）。期望值不能从被测配置或同一映射函数反推。GLB 能加载、位置变化、角度数值相等、映射往返成立都不足以证明朝向正确。
4. 攻击使用独立确认的枪口／炮管／骨骼参照与真实目标方向检查；2D 还需核对原帧的起始方向、顺逆时针、帧号和镜像。观察游戏实际尺度的移动及攻击，保存多方向截图或短录屏；单张静态正面图不算运动验收。
5. 用户发现方向错误后增加失败→通过回归，旧错误偏移必须触发失败。报告逐模型覆盖及未验证项，不将移动通过扩写成攻击／炮塔全部通过。
