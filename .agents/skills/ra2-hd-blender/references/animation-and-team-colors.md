# 动作、交互与阵营换色

以单位实际原素材和游戏状态为依据，制作动作并在同地图验证；特效不代替模型动作。

## 按类型制作

- 双足步兵：核对 SHP 序列后制作适用的待机、走跑、射击、卧倒／起身、匍匐、游泳等。进入载具、维修、占领、死亡只按实际能力及本次范围；方法见 [骨骼适配](skeletal-motion.md)。
- 车辆／船只：保留可恢复 VXL/HVA 与独立部件，建立车体、炮塔、炮管、车轮／履带的层级、pivot 和方向映射。分层精灵需检查排序、接缝和枪口位置。不能把整车旋转当炮塔瞄准，或给机械模型套人形自动绑定。
- 建筑：分别核对底座、工作、受损、维修、建造／摧毁状态和阴影。机械组件用相应运动轴／层；没有来源或未制作的状态标缺失。
- 开火、命中、烟火、爆炸、血量和交互标记由真实引擎事件驱动，保留原游戏反馈。模型升级不改变伤害、射程、射速和移动规则。原版天启有炮塔但未启用 OpportunityFire，不能默认加入行进射击；新单位查自己的规则。

## 方向与运动

移动、朝向烘焙或 3D 交互任务必读 [方向映射与行为验收](direction-mapping.md)。逐资产确认车头／身体前向，验证八方向真实位移、攻击轴及观察转向后的移动恢复；不能用配置自洽或模型位置变化替代实际朝向验收。未支持的机械状态仍标缺失。

## 阵营色与烘焙

按原素材确认阵营服装／标识，保留独立 remap mask 或材质区域；只改指定区域，不把谭雅的背心范围当作所有单位的换色范围。骨骼 mask 随蒙皮、机械 mask 随部件移动，并保留亮暗。

几何选区先验证 source rest 坐标与实际蒙皮位置的关系，避免重复应用 armature 缩放后高度阈值失效。结合材质／纹理区分服装和皮肤；Tanya 的躯干权重、位置范围与橄榄色阈值只是实例。3D 换色和 Canvas mask 共用选区与明暗逻辑；自定义 GLB 属性需要消费端材质支持，不能声称任意查看器都会换色。

按 [Canvas 烘焙规范](runtime-optimization.md#canvas-2d-验证路径) 输出 action、facing、frame、fps、pixelRatio、锚点、frameRects 和事件映射。裁空白时同步记录每帧锚点；阴影按原映射单独处理。用实际颜色选择器及玩家颜色检查多朝向、屈身和动作边界：可见服装应有非空 mask，切色后 mask 外像素不变。检查裁切、脚底滑动与缓存回收，报告 PNG 下载大小和解码尺寸。

## 同地图循环检查

现有 `GameEngine` / `BattlefieldRenderer` 只读 PNG 和 mask。将原版与 HD 单位同地图并排，同步世界位置、朝向、动作和时间。使用原水面、岸线、坡道与高度；不要另画临时地形，也不要开额外场景窗口代替地图检查。缺少本地原素材时说明尚不能完成这一验收。

按单位能力安排自动循环，并允许手动指挥与检查：移动／停止、瞄准／射击、受击；双足适用的卧倒／卧射、游泳／踩水／水中射击；建筑工作／维修等。一次性死亡循环可在预览中重置实例；持续受击靶保留少量 HP（当前预览 2%），仅在 preview 中实施，正常游戏逻辑不变。

提供暂停、慢放、逐帧、方向和队伍色选择。检查左右脚交替、位移与步频、枪口方向、水线遮挡、坡上坡下和选择／排序。支持中英文时沿用现有语言切换。自动检查通过后仍观察游戏实际尺度的动作。

## 当前能力与证据入口

- 谭雅已有骨骼 GLB 与源帧对应图集，具体覆盖、重建局限及正确烘焙入口见 [实例](tanya-motion-example.md)。其动作不是逐像素恢复原版。
- 其它三个 30k 样本仍为静态网格，车辆后坐／车体震动、建筑损伤／维修反馈不等于独立炮塔、履带或完整建造动画。新增单位仍需适配和验证。
- `tools/canvas-hd-preview/test-actions.mjs` 检查真实指令、伤害、维修、暂停与换色；`tools/tanya-motion/motion.test.mjs` 检查真实骨骼轨迹和帧覆盖。旧 `procedural-poses.test.mjs` 仅验证旧程序变形，不能作为骨骼交付证明。
