# 动作、交互与阵营换色

## 验收依据

以实际游戏状态为驱动，先检查该单位已有的指令、伤害与互动逻辑。动作与规则
分开：不通过预览特效改变伤害、射程、射速或移动规则。静态 GLB 的多朝向图集
不等于有动画；只有原模型含可用动画／部件或另有动作源，才能声明对应能力。

- 人物：待命、转向、行走／奔跑、瞄准与开火、受击；死亡及进入载具、维修、
  占领等只按单位实际能力制作。循环动作与一次性事件分别计时，事件帧从事件
  发生时刻开始，暂停和慢放同步。
- 车辆：车体／履带运动、炮塔瞄准、炮管后坐、命中及损毁。独立炮塔需要独立
  部件或分层精灵及旋转轴，不能把整辆坦克旋转当成炮塔转动。移动中是否开火
  按实际规则验证；原版 RA2 天启有炮塔，但未开启 OpportunityFire，不能据此
  默认加上行进射击。当前引擎同样在移动指令下不射击。
- 建筑：适用的工作、受损、维修、建造和摧毁状态。没有对应动作时明确标缺失。
- 反馈：按真实开火／伤害事件显示枪口焰、弹道、命中、爆炸和血量变化，选择、
  指令标记、维修等反馈沿用引擎。显示特效不代表角色本身已有完整动作。

## 动作来源与保留

优先复用已有 rig、动画 clips 和命名部件，减面时保留骨骼权重、UV 与动画数据。
没有绑定时，可为当前模型做程序姿态或分部件预览，标明来源、局限和未完成项；
不要为获得动画擅自重跑付费生成任务。空间分区变形只是预览，不是通用自动绑定。

Canvas 输出需记录 action、facing、frame、fps、pixelRatio、锚点和事件时间映射。
图集尽量裁去空白并保留一致坐标，不同朝向与动作检查裁切、脚底滑动、瞄准方向、
遮挡和抖动。glTF 属性可能交错存储，操作顶点时使用正确的 stride／属性访问器。

入库动作配方／必要轻量动画源、选定图集、换色遮罩和生成记录；不为每个动作重复
归档高模、FBX、Blender 工程。静态 GLB＋程序烘焙帧要明确说明 GLB 本身仍无 clips。

## 阵营色

保留独立 remap mask 或材质区域定义。只改变旗帜、装甲标识、服装阵营区域，
保留亮暗、皮肤、金属及非阵营图案。遮罩跟随原部件／服装区域，不能因举枪后
位置变化而误染手和枪械。多队颜色分别可选；切换颜色时回收旧缓存，避免不断
复制大图集。验证多朝向与所有动作，比较换色前后遮罩外的像素是否保持一致。

## 当前预览能力与检查

`npm run viewer:glb` → `/canvas/` 使用 GameEngine / BattlefieldRenderer，运行时
只读取 PNG 与 remap mask。左键选我方，右键地面移动／靶标攻击，靶标默认不还击；
可开启还击、维修选中建筑、暂停、慢放及队伍换色。

当前 Tanya 是 8 朝向的程序行走、举枪、受击帧；天启是车体震动／后坐与战斗特效。
四个 GLB 仍是静态网格。完整骨骼绑定、履带动画、独立炮塔、角色死亡动作及其它
未展示的互动尚未完成，不以这些样本代表全游戏动态资产已齐全。

验证入口：`tools/canvas-hd-preview/test-actions.mjs` 检查真实鼠标指令、伤害、维修、
暂停与遮罩换色；`procedural-poses.test.mjs` 检查交错顶点的静止姿态不被破坏。
同时观察实际渲染，自动测试通过不能替代外形与动作检查。
